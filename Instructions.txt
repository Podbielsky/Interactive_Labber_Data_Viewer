Installation Instructions for Windows Systems (updated 20.08.2026)

------------ |
Requirements |
------------ |
- A 64-bit Windows system
- An internet connection during setup
- Windows PowerShell

Installation
->
1. Keep set_up_labber_hdf5_GUI.bat, labber_hdf5_viewer.bat, and the
   source and icons folders together in the same folder.

2. Double-click set_up_labber_hdf5_GUI.bat. The setup script will:
   - Look for Python 3.10 in
     %USERPROFILE%\AppData\Local\Programs\Python\Python310.
   - Automatically download and install the newest Python 3.10 version
     with an official Windows installer if Python310 is not present.
   - Create or update the Labber_View_GUI virtual environment.
   - Install the required Python packages, including matplotlib 3.5.0.
   - Copy the application files into the virtual environment.
   - Record the installed Git commit for update checks.
   - Create a "Labber HDF5 Viewer" shortcut on the current user's Desktop.
     The shortcut uses icons\labber_viewer_ICON.ico as its icon.

3. Wait until the setup window reports that the Desktop shortcut was
   created successfully.

Starting the viewer
-->
- Double-click the "Labber HDF5 Viewer" Desktop shortcut.
- Alternatively, double-click labber_hdf5_viewer.bat.

Notes
--->
- Python is installed only for the current user. Administrator rights
  should not be required.
- Python is not added to the system PATH, which avoids conflicts with
  other installed Python versions.
- Python 3.10.11 is used because it is the final Python 3.10 release with
  an official Windows installer. Later Python 3.10 security releases are
  source-only.


Installation Instructions for macOS and Linux

------------ |
Requirements |
------------ |
- macOS 13 or newer, or a 64-bit glibc-based Linux system
- An internet connection during setup
- Bash and either curl or wget

Installation
->
1. Keep set_up_labber_hdf5_GUI.sh and the source and icons folders together
   in the same folder.

2. Open Terminal in that folder and run:

   chmod +x set_up_labber_hdf5_GUI.sh
   ./set_up_labber_hdf5_GUI.sh

3. The setup script will:
   - Install or update uv inside the current user's data folder.
   - Install the newest available Python 3.10 patch release for the current
     user. Administrator rights are not required.
   - Create or update the Labber_View_GUI virtual environment.
   - Install the required packages, including matplotlib 3.5.0.
   - Copy the application and icon files into the user installation.
   - Record the installed Git commit for update checks.
   - On macOS, create "Labber HDF5 Viewer.app" on the Desktop.
   - On Linux, create a Desktop shortcut and an application-menu entry.

Starting the viewer
-->
- macOS: double-click "Labber HDF5 Viewer.app" on the Desktop.
- Linux: double-click the Desktop shortcut or select "Labber HDF5 Viewer"
  from the application menu.

Notes
--->
- The user-local installation is stored below
  ${XDG_DATA_HOME:-$HOME/.local/share}/Labber_View_GUI.
- The setup uses uv-managed Python builds from Astral's
  python-build-standalone project so that the same installer works without
  sudo on both macOS and Linux.
- Python is not added to the system PATH.
- On Linux, the desktop environment may ask you to confirm "Allow Launching"
  the first time the shortcut is used.


Changing the interface style
-->
- Open the Style menu next to File, Data, and Plotting.
- Choose a theme from the Light or Dark submenu.
- The selected theme is applied immediately to all open viewer windows.
- The selected theme is remembered and restored the next time the viewer starts.


Opening HDF5 and NPZ files with drag and drop
-->
- Drag one .hdf5, .h5, or .npz file from the file manager onto the HDF5 file
  tree.
- The viewer validates and opens a dropped HDF5 file immediately.
- A dropped NPZ archive is converted to an HDF5 file with the same base name in
  the same directory. The converted file is then opened automatically. If that
  HDF5 file already exists, the viewer asks before replacing it.
- NPZ loading and HDF5 writing run in the background after field assignment.
  The message above the file tree shows the conversion status.
- If the archive contains three or more fields, a selection window asks which
  fields represent x, y, and z. Fields named x, y, and z (case-insensitive) are
  preselected when available. Each role must use a different field.
- If an NPZ archive contains exactly two fields, the selection window asks which
  field is x and which is z. The converter creates the missing y coordinate as
  the one-value array [0.0].
- z may be a 1D or 2D real numeric array. A 1D z array is treated as a map with
  one row. x and y must be real numeric 1D arrays or 2D coordinate grids.
- For a 2D z array with shape (rows, columns), a 1D x array must contain one
  value or "columns" values, and a 1D y array must contain one value or "rows"
  values. A 2D x or y grid must have exactly the same shape as z.
- Before opening the assignment window, the viewer verifies that every field is
  a NumPy array that can be read without pickle. Object arrays that require
  Python pickle loading are rejected and reported by field name.
- Drop only one file at a time. Files with spaces in their names are supported.
- If a measurement database is active, a dropped HDF5 file (including one
  created from NPZ) is copied into the database's "Drag and Drop" directory.
  The managed copy is opened. An identical file already in the database is not
  copied again.


Using the optional measurement database
-->
- The database is disabled by default. Its location is stored as
  "database_folder" in the user-local preferences.json file; the default value
  is null.
- Select File > Set Database Folder... and choose a directory. The viewer
  creates a portable SQLite index in its hidden .labber_viewer directory and a
  "Drag and Drop" import directory.
- Creating or selecting a database starts a recursive background scan. Valid
  viewer-compatible .hdf5 and .h5 files are indexed. Other HDF5 layouts,
  unreadable files, and symbolic links are skipped.
- Measurement paths are stored relative to the selected database directory.
  Keep or copy the complete database directory when moving it to another disk.
- Select File > Browse Database... to open the database overview. This command
  is disabled while no valid database is configured.
- The left side of the browser reproduces the database directory structure.
  Click a measurement once to load its map preview. The preview uses the last
  logged data channel and the final slice of higher-dimensional measurements.
- Measurements containing only one sweep-axis channel are shown as linecuts in
  the database preview. Opening the measurement in the map viewer repeats the
  line across a synthetic three-row Y axis named "y-dummy", so the existing
  crosshair, linecut, and displayed-data tools remain available.
- Preview loading reads only that two-dimensional HDF5 slice and samples at
  most 256 points per displayed axis directly from disk. It does not construct
  the complete multidimensional measurement array.
- Very large map planes use a smaller 64- or 128-pixel raster automatically.
  Only one preview is read at a time; when the selection changes quickly, the
  viewer keeps the newest pending selection instead of starting parallel reads.
- When the measurement tree has keyboard focus, use the Up and Down arrow keys
  to move directly between measurements and update the preview. Folder entries
  are skipped.
- Click the same measurement again, press Enter, or select "Open Selected" to
  load its managed HDF5 path in the main file viewer.
- Use "Mark as special measurement" to add a star. Comments entered below the
  preview are stored after selecting "Save Comment". Stars and comments remain
  available after restarting or rescanning the application.
- Select "Rescan Database" after adding, moving, renaming, or deleting files
  directly inside the database folder. A uniquely identified moved file keeps
  its existing star and comment.
- Files dragged into an active database are copied atomically, checked for
  corruption, and given a collision-free filename. The database copy remains
  usable if the original file is later moved or deleted.
- Database indexing, hashing, file copying, and preview extraction run in
  background threads. Large databases may take time to scan but should not
  freeze the interface.


Displaying maps acquired with alternating X sweeps
-->
- Open the measurement with Plotting > Plot Map or Plot Map with Trace Data.
- In the map window, use the "X sweep direction" radio buttons and select
  "Alternating" when the acquisition reversed the X sweep on every second row.
- The viewer reverses every second signal row and normalizes stored X-coordinate
  rows when necessary. The map, crosshair, ROI, linecuts, displayed-data export,
  and trace selection then use the corrected ordering.
- Select "Normal" for measurements acquired in the same X direction on every
  row. Normal is the default and one-axis measurements keep this setting.


Map rendering, crosshairs, and numerical precision
-->
- The map viewer retains the active X, Y, and signal calculation arrays at
  float64 precision. Filters, derivatives, integrations, linecut extraction,
  ROI operations, undo states, and displayed-data exports use these full-
  resolution arrays.
- The color map is rendered from separate float32 arrays. They are regularly
  sampled to approximately one data point per available map-canvas pixel and
  are regenerated after an explicit data operation or a debounced window
  resize. The first and last source rows and columns are always retained.
- The horizontal and vertical crosshair linecuts have independent Matplotlib
  canvases. Crosshair motion retains only the newest requested position and
  updates the cursor, data-cell lookup, and persistent line artists together at
  a maximum rate of approximately 30 Hz. Each displayed line is limited to 512
  points and is blitted over cached axes.
- "Fast crosshair" is enabled by default in the controls to the right of the
  plot, above the X-sweep selection. It uses the operating-system crosshair
  cursor without moving full-width guide lines over the map bitmap. Clear this
  checkbox to show the horizontal and vertical guide lines; those lines remain
  rate-limited and are kept above the color map after redraws. Press S while
  the map has keyboard focus to freeze or unfreeze the current crosshair and
  linecuts.
- ROI selection and new-line drawing use rate-limited native canvas outlines
  while the pointer moves. Their permanent Matplotlib artists are created only
  after the second click, so motion does not repeatedly redraw the color map.
- Maps continue to use pcolormesh. Expensive per-motion QuadMesh hit-testing is
  disabled, while toolbar coordinate reporting and pan/zoom remain available.
- Non-blitted Matplotlib figures use transparent figure and axes patches. The
  two fast linecut canvases instead use an opaque background matched to the
  active ttk theme: TkAgg needs those opaque cached pixels to erase the previous
  blitted curve without leaving trails. The result still blends into the GUI
  instead of showing a separate white plotting canvas.
- In the map-with-traces viewer, the selected time trace also uses an
  independent canvas, so changing the selected trace does not repaint the map.


Checking for updates
-->
- The viewer silently checks the repository's main branch shortly after startup.
- If newer commits are available, a window displays their commit messages and
  the changed-file summary compared with the installed commit.
- Select Help > Check for Updates... to run the check manually at any time.
- Select "Open comparison on GitHub" in the update window to view the complete
  comparison in a web browser.
- Select "Install update and restart" to download the changed application files
  from the exact main-branch commit, install them, and restart the viewer.
- Updates are validated before installation and are rolled back if replacing a
  program file fails.
- If requirements.txt changed, run the newest setup script instead so that the
  Python environment and application files are updated together.
- Automatic installation is disabled when running directly from a Git source
  checkout to avoid overwriting local work. Update that checkout with Git.
- Checking for and installing updates requires an internet connection.
